## 1. 最终交付目标与范围

成品应能在目标 Windows PC 上独立安装或解压运行，完成：

启动 → 主菜单 → 选择角色/群系 → 随机无限地图探索 → 自动战斗/手动标记/Shift 闪避 → 随机升级与定向购买 → 主动挑战 Boss/脱战 → 撤离或死亡结算 → 永久成长与任务解锁 → 再次开局。

### 必须覆盖的已确认内容

- 明快卡通 3D、A 方向 Q 版角色、固定朝向跟随镜头与滚轮缩放。
- 魔法、枪械、修仙可完全混搭，武器与被动无槽位上限，同一武器的小路线可同时获得。
- 首批三件基础武器：火球、自动手枪、飞剑。
- 已列出的 15 个强化/新增能力选项及 3 个跨体系联动，详见 GameDesign 第 7 节。
- 新角色、新升级选项等通过任务解锁；永久属性通过局外资源提升。
- 林地、荒漠、雪原、火山，四种无限单群系地图及全群系混合地图。
- 四个群系 Boss 的主动挑战、自由脱战、首次击败解锁链与全群系地图奖励。
- 自由撤离、继续无限生存、死亡保留已获得的永久资源与累计成果。
- 完整菜单、局内 UI、任务/解锁展示、设置、结算、存档、音效和成品美术。

### 在 M0 冻结的详细内容清单

“很多小分支”不是可逐项验收的数量。M0 需创建具体内容清单，逐条列出角色、每个体系的小分支、能力、任务、敌人、事件、Boss 招式、地图模块、UI、美术和音频；每项记录 ID、依赖、完成定义及状态。

- 角色至少覆盖初始可玩角色与任务解锁角色；具体数量和差异化特性列清单。
- 三个大体系分别列出首发的小分支，明确首批三条之外还纳入哪些分支及其完整成长路线。
- 如需范围建议，可从每体系两条小分支展开；这是新提出的制作规模建议，并非此前已确认数量。
- 已有技能草案和四群系是最低基线，不能以只完成林地测试场景作为成品。
- 未列入首发清单的后续扩展单独记录，不让首发范围无限增长。
- 局内中断续玩、首发语言、发行渠道和最低配置在此阶段明确；当前不把尚未决定的项目宣称为既有功能。

## 3. M0：范围、技术与工作清单

工作：

- 记录 Unity 版本、当前管线、UGUI/TMP、输入系统和目标 Windows 架构。
- 建立版本管理、Unity 忽略规则和可恢复的项目基线；`.meta`、包清单与锁文件必须保留。
- 冻结首发内容清单，标明已确认功能、制作默认和待定设计。
- 登记实际测试机 CPU/GPU/内存，确定分辨率、帧率、内存、包体与加载时间预算。
- 选择并锁定兼容 Addressables 版本，验证一次最小内容构建。
- 将未定的闪避方向/碰撞、索敌偏好、升级候选数、刷新、数值叠加、Boss 重复挑战规则写入决策表，先采用明确的原型默认并通过试玩调整。

验收：版本和清单可追溯；预制体路径规范可检查；AA 示例能在 Player 内离线加载；性能目标标注测试机，禁止编造结果。

## 4. M1：先打通启动、UI、AA 和清理

工作：

- 建立 Boot 和唯一 GameManager，创建 UIManager、AssetService 及明确的初始化顺序。
- 实现菜单→准备→测试局→返回菜单的状态迁移和故障回退。
- 在 `Art/Prefabs/UI` 制作 UIRoot、加载遮罩、主菜单和基础错误页面，经 AA 加载。
- 封装资产租约、实例租约、场景操作和作用域；覆盖并发、关闭先于加载完成、失效请求迟到回收。
- 建立 AA 内容登记和预制体路径检查工具；检查重复 ID、缺资源、Missing Script 与禁止的旁路加载。
- 输出第一个 Windows 开发构建，验证真实包中的 AA 内容路径。

验收：连续多次进出局不产生重复 Manager、Canvas、EventSystem、事件订阅或本局资源租约；资源不存在和加载失败时可重试或返回；关闭加载中的 UI 不留下迟到页面。

## 5. M2：可玩战斗原型

工作：

- 使用 Q 版比例临时 3D 角色验证移动、转向、相机跟随和缩放。
- 实现 Shift 闪避及可观察的无敌窗口，明确边界、受击间隔与状态恢复。
- 实现默认索敌、右键标记/切换/取消、血条与目标失效处理。
- 依次接入普通追击怪、快速怪、冲锋怪、远程怪及清晰攻击预警。
- 实现三武器、投射物、命中、生命、死亡、掉落和对象池。
- 加入基础命中反馈与临时音效，检查输入穿透和边缘碰撞。

验收：能移动、闪避、标记并用三武器同时清怪；无敌窗口内外受伤符合规则；目标死亡、越界或遮挡不导致永久停火；对象复用不残留上次目标和状态。

## 6. M3：自由组合与两种成长入口

工作：

- 建立属性、标签、数值修改器与额外攻击形态的统一应用规则。
- 接入经验升级、随机候选、定向资源、技能树与购买校验。
- 所有配置使用稳定 ID；首次获得、重复强化和机制解锁清晰区分。
- 加入三个首批分支的强化与代表性联动，验证后继续扩充首发清单。
- UI 展示已拥有能力、等级、适用对象、购买价格与任务解锁条件。
- 实现升级选择和技能树暂停，验证嵌套弹窗关闭顺序。

验收：飞剑追击、绕身剑阵和剑雨能共存；枪械连射/散射/穿透/弹射能组合；随机获得与购买同一能力结果一致；资源不足、重复点击和未解锁购买均正确处理；无武器或被动槽位限制。

## 7. M4：无限地图基础

工作：

- 先制作林地的地形模块、随机规则、区块坐标和稳定种子生成。
- 实现区块预取、加载、卸载、对象池和每帧生成工作预算。
- 保存地标、事件和已领取奖励的区块变更；地形和持久状态分开。
- 实现小地图、探索记录、地标提示与目的地标记。
- 验证地形衔接、可行走路径、出生点和 Boss 地标可达。
- 引入浮动原点并验证投射物、拖尾、相机和物理对象同步。

验收：同种子/坐标生成同地形；返回旧区不变形、不重复领奖；跨区块、原点移动、快速移动不会落空或刷到不可达位置；运行驻留区块和内存不随总探索面积持续增长。

## 8. M5：林地完整流程样板

工作：

- 接入林地精英营地、至少一种事件和古树守卫的完整行为。
- Boss 由地点交互主动激活，提供招式预警、边界提醒和脱战缓冲。
- 脱战后重置 Boss，清理战斗专属残留，允许重新挑战。
- 胜利当场记录任务和首胜，提供继续/撤离选择；早期也可主动撤离。
- 接入死亡、撤离、资源结算与菜单返回，预留永久进度接口。

验收：从启动到结算完整走通；玩家可在准备不足时离开 Boss，成长后返回；继续后死亡不撤销已完成首胜；同局结算至多一次；不因计时结束强制召唤 Boss。

阶段成果是完整流程样板，并非最终成品：其余地图、永久进度和正式内容仍需后续阶段完成。

## 11. M8：美术、音频、UI 与引导

角色/怪物流程：概念确认 → 模型 → UV/贴图/材质 → 骨骼与蒙皮 → 移动/攻击/受击/死亡等动画 → 碰撞与挂点 → 包装预制体 → AA → 游戏内验证。

地图流程：配色与模块规范 → 地形/植被/建筑/地标 → 碰撞与遮挡 → 生成规则 → 群系特效与音景 → AA → 边界和长距离探索验证。

UI 流程：页面结构与数据需求 → 视觉稿 → UGUI/TMP 预制体 → UIManager 登记 → 数据绑定与命令 → 多分辨率/中文字体/输入验证。

工作：

- 正式资源替换临时资源，保持已验证的碰撞和操作手感。
- 完成主菜单、角色/地图选择、HUD、升级、技能树、任务、永久成长、暂停设置、加载、结算和解锁提示。
- 制作武器/命中/状态/Boss 特效与音效、群系音乐、音量与显示设置。
- 完成必要的新手提示和未解锁条件说明，允许跳过已理解的提示。
- 技能再密集也保留玩家、敌方预警、标记目标和交互物的辨识度。
- 登记资源来源及使用范围，交付所需源文件和导入参数。

验收：正式资源无 Missing Script/材质丢失；全部预制体在约定目录并正确登记 AA；中文不缺字、文本不溢出、模态输入不穿透；大量特效下仍能判断危险。

## 12. M9：性能与数值收敛

性能：

- 在 M0 指定机器上记录真实 Player 的 CPU/GPU 帧时间、内存、GC、加载和存档耗时。
- 压力矩阵覆盖敌人数、投射物、飞剑/召唤物、多能力叠加、快速跨区块与混合群系边界。
- 对空间查询、调度、对象池、UI 刷新、特效和包依赖的实际热点逐项优化。
- 长距离探索与至少两小时无限生存压力测试，检查内存与帧时间趋势。
- 提供不同视觉质量设置，确认降级仅影响表现而不减少组合能力与实际伤害。

平衡：

- 检查初次游玩与永久属性较高时的成长节奏。
- 检查新能力获取、重复强化、定向资源产出、价格和刷新策略。
- 覆盖单体系深入、跨体系混搭、大量能力同时持有与较早挑战 Boss。
